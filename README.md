# mac-du

macOS 터미널에서 디렉토리별 디스크 사용량을 보여 주는 TUI 도구입니다.
현재 디렉토리의 하위 파일과 폴더를 용량 순으로 정렬해 막대 그래프와 함께 보여 주고, 폴더 안으로 들어가며 어디서 공간이 많이 쓰이는지 찾아갈 수 있습니다.

> **상태:** 개발 초기 단계입니다. 목록 조회, 폴더 드릴다운, 병렬·백그라운드 스캔까지 구현되어 있습니다. 삭제 등 정리 기능은 아직 없습니다.

## 요구 사항

- macOS
- Rust 1.85 이상 (edition 2024)

Rust가 없다면 [rustup](https://rustup.rs)으로 설치합니다.

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

## 설치 및 실행

```bash
git clone https://github.com/HaruDorobou/rustonmac_macdu.git
cd rustonmac_macdu
cargo run --release
```

`--release`를 권장합니다. 파일시스템 호출이 많은 작업이라 디버그 빌드는 더 느립니다.

어느 디렉토리에서든 실행하려면 설치합니다.

```bash
cargo install --path .     # ~/.cargo/bin/mac-du 로 설치
cd ~/Downloads && mac-du
```

## 사용법

```bash
mac-du [옵션]
```

실행하면 현재 작업 디렉토리를 기준으로 화면이 그려집니다.

### 명령줄 옵션

| 옵션 | 설명 |
| --- | --- |
| `-j`, `--threads <N>` | 스캔에 쓸 스레드 수 (1 이상). 기본값은 `min(CPU 코어 수, 16)` |
| `-r`, `--root <DIR>` | DIR 전체를 미리 스캔해 두고 화면은 현재 폴더에서 시작 ([미리 스캔](#미리-스캔---root) 참고) |
| `-w`, `--watch <SEC>` | 시작하자마자 [감시 모드](#감시watch-모드)를 켜고 SEC초마다 현재 폴더를 다시 스캔 (2 이상, 상한 없음) |
| `-h`, `--help` | 도움말을 출력하고 종료 |

`--threads`는 `-j 8`, `--threads 8`, `--threads=8` 형태로 쓸 수 있습니다.
값이 잘못되었거나 알 수 없는 옵션이면 오류 메시지를 출력하고 종료 코드 2로 끝납니다.

```bash
mac-du                 # 기본 설정으로 실행
mac-du --root ~         # 홈 전체를 미리 스캔해 두고 현재 폴더에서 시작
mac-du -w 5            # 5초마다 현재 폴더를 감시
mac-du -j 8            # 스캔 스레드를 8개로 제한
mac-du --threads=4     # 같은 의미, 다른 표기
mac-du --help
```

> **주의:** `--threads`로 CPU 코어 수보다 큰 값을 지정하면 스캔이 수 초씩 멈출 수 있습니다. 아래 [용량 계산 방식](#용량-계산-방식)의 병렬 스캔 항목을 참고하세요.

`mac-du --help` 출력:

```
mac-du - macOS 디스크 사용량 TUI

사용법:
    mac-du [옵션]

옵션:
    -j, --threads <N>    스캔에 쓸 스레드 수 (1 이상).
                         기본값은 min(CPU 코어 수, 16)입니다.
                         코어 수보다 크게 지정하면 스캔이 수 초씩 멈출 수 있습니다.
    -r, --root <DIR>     DIR 전체를 미리 스캔해 두고, 화면은 현재 폴더에서 시작합니다.
                         DIR 아래에서는 어느 폴더로 오가도 다시 스캔하지 않습니다.
                         시작 시 DIR 전체를 읽으므로 넓은 경로일수록 오래 걸리고 메모리를 씁니다.
                         현재 폴더가 DIR 밖이면 DIR에서 시작합니다.
    -w, --watch <SEC>    시작하자마자 감시 모드를 켜고 SEC초마다 현재 폴더를 다시 스캔
                         (2 이상, 상한 없음). 큰 폴더라 스캔이 오래 걸리면 간격이 자동으로 늘어납니다.
                         앱 안에서는 w 키로 켜고 끄고, +/- 키로 간격을 바꿉니다.
    -h, --help           이 도움말을 출력하고 종료

환경 변수:
    RAYON_NUM_THREADS    --threads를 지정하지 않았을 때 스레드 수로 사용
```

### 키 조작

| 키 | 동작 |
| --- | --- |
| `j` / `↓` | 아래 항목으로 이동 |
| `k` / `↑` | 위 항목으로 이동 |
| `l` / `→` / `Enter` | 선택한 폴더 안으로 들어가기 (파일은 무시) |
| `h` / `←` / `Backspace` | 상위 폴더로 올라가기 (떠나온 폴더가 선택된 상태로 열림) |
| `r` | 지금 보고 있는 폴더 하위만 다시 스캔해 갱신 (파일이 바뀌었거나 권한을 허용해 준 뒤) |
| `p` | 위쪽 폴더를 골라 그 폴더까지 미리 스캔해 두기 ([미리 스캔](#미리-스캔---root) 참고) |
| `w` | 감시 모드 켜기/끄기 |
| `+` / `-` | 감시 간격 늘리기/줄이기 (감시 중일 때. `+`는 Shift 없이 `=`로도 됩니다) |
| `e` | 읽지 못한 경로 목록 열기/닫기 (오류가 있을 때만) |
| `q` / `Esc` | 종료 |

### 화면 구성

- **헤더**: 현재 경로, 전체 합계, 이번 스캔에 걸린 시간 (예: `합계: 128.1 GB · 스캔 1.04초`). 스캔 중에는 스피너와 대상 경로가 표시됩니다. 읽지 못한 경로가 있으면 `⚠ 읽지 못한 경로 N건 (e)`가 함께 표시됩니다.
- **목록**: `크기 · 비율 · 막대 그래프 · 아이콘 · 이름` 순서로, 크기 내림차순 정렬. 폴더는 📁, 파일은 📄로 표시됩니다. 안에서 읽지 못한 경로가 있는 항목에는 노란색 `⚠ 읽지 못함 N`이 붙습니다. 이 항목의 크기는 실제보다 작습니다.
- **푸터**: 키 도움말. 폴더를 열 수 없으면 빨간색 경고 메시지가 대신 표시됩니다.

### 동작 참고

- 스캔은 백그라운드에서 돌기 때문에 화면은 멈추지 않습니다.
- 시작한 폴더를 한 번 스캔하면 하위 전체의 크기를 메모리에 트리로 들고 있어서, 그 아래 폴더로 들어가고 나오는 것은 **다시 스캔하지 않고 즉시** 됩니다. 스캔이 필요한 경우는 시작할 때, `r`을 누를 때, 그리고 시작한 폴더보다 위로 올라갈 때뿐이며, 위로 올라갈 때도 이미 읽은 부분은 다시 읽지 않고 나머지(형제 폴더들)만 읽습니다.
- 스캔 결과는 프로그램을 끌 때까지만 유지되고 디스크에는 저장하지 않습니다. 그동안 파일이 바뀌면 화면은 낡은 값이므로 `r`로 갱신하세요.
- 심볼릭 링크는 폴더로 취급하지 않으므로 들어갈 수 없습니다.

### 감시(watch) 모드

`w`를 누르면 지금 보고 있는 폴더를 일정 간격으로 자동으로 다시 스캔하고, **직전 스캔과 비교해 무엇이 달라졌는지** 화면에 표시합니다. 빌드 결과물이나 다운로드, 캐시 폴더처럼 어디서 용량이 늘고 있는지 지켜볼 때 씁니다.

변화는 눈에 띄도록 여러 곳에 표시됩니다.

| 위치 | 표시 |
| --- | --- |
| 목록의 항목 | 커진 항목은 빨간색 `▲ +120.0 MB`, 줄어든 항목은 초록색 `▼ -3.0 MB`, 새로 생긴 항목은 `NEW 50.0 KB` |
| 막 바뀐 항목 (3초 동안) | 행 맨 앞에 `●`가 찍히고 이름과 증감이 굵게 표시됩니다. 이후 30초 동안은 굵기와 `●` 없이 증감만 남았다가 사라집니다. |
| 헤더 둘째 줄 | `⟳ 감시 5초 · 다음 3초 후 · 확인 2초 전 · 마지막 변화 ▲ +120.0 MB (4초 전)` |
| 헤더 테두리 | 변화가 감지된 순간 1.5초 동안 노랗게 깜빡입니다. 감시 중에는 평소 청록색입니다. |

- **간격:** 기본 5초이고, `+`/`-`로 `2 · 3 · 5 · 10 · 15 · 30 · 60 · 120 · 300 · 600 · 1800 · 3600`초 단계로 바꿉니다. 3600초를 넘으면 두 배씩 늘어나며 **상한은 없고, 최솟값은 2초**입니다. `--watch <SEC>`로 시작할 때 지정할 수도 있습니다.
- **스캔이 겹치지 않습니다:** 다음 간격은 이전 스캔이 *끝난 뒤부터* 잽니다.
- **큰 폴더는 자동으로 느려집니다:** 실제 간격은 `max(설정한 간격, 마지막 스캔 시간 × 2)`입니다. 스캔에 6초 걸리는 폴더를 2초 간격으로 감시해도 12초마다만 읽어서 디스크를 계속 읽지 않습니다. 이때 헤더에 `(스캔이 오래 걸려 12초)`가 표시됩니다.
- **화면이 깜빡이지 않습니다:** 갱신하는 동안에도 기존 목록을 그대로 보여 주고 헤더에 `갱신 중…`만 표시합니다. 보던 위치와 선택도 유지됩니다.
- **현재 폴더 하위만 읽습니다:** 보고 있는 폴더 아래만 다시 스캔하므로 깊이 들어가 있을수록 가볍습니다. 폴더를 옮기면 감시는 새로 보는 폴더를 따라갑니다.
- 수동으로 `r`을 눌렀을 때도 같은 방식으로 변화가 표시됩니다.

### 미리 스캔 (`--root`)

기본적으로는 **시작한 폴더만** 스캔합니다. 그래서 시작 폴더보다 위로 올라가면 부모 폴더의 나머지를 읽어야 합니다. 위쪽 폴더들을 자주 오갈 것 같다면 넓은 경로를 미리 스캔해 둘 수 있습니다. 두 가지 방법이 있습니다.

**1. 실행 중에 `p` 키로** — 지금 위치의 상위 폴더들(예: `/Users/me/work`, `/Users/me` (홈), `/Users`, `/` (디스크 전체))이 팝업으로 나옵니다. `j`/`k`로 고르고 `Enter`를 누르면 그 폴더까지 스캔하며, 홈 디렉토리가 후보에 있으면 처음부터 선택되어 있습니다.

- 스캔하는 동안에도 지금 보던 화면과 위치가 그대로 유지되고 헤더에 `⠋ /Users/me 까지 스캔 중…`이 표시됩니다. 그 사이에도 폴더를 옮겨 다닐 수 있습니다.
- **이미 스캔한 부분은 다시 읽지 않고** 위쪽의 나머지만 새로 읽어 끼워 넣습니다. (이 기기에서 홈을 이미 읽은 상태로 `/Users`까지 넓히는 데 약 3ms, 처음부터 읽으면 약 2.5초였습니다.)
- 이미 최상위(`/`)까지 스캔했다면 "이미 최상위 폴더까지 스캔했습니다"라고 알려 줍니다.

**2. 시작할 때 `--root`로**

```bash
cd ~/Workbench/my_rust_project/mac-du
mac-du --root ~        # 홈 전체를 먼저 스캔하고, 화면은 지금 폴더에서 시작
```

- `--root` 아래에서는 어느 폴더로 올라가고 내려가도 **다시 스캔하지 않습니다**. 형제 폴더로 옮겨 가는 것도 즉시입니다.
- 대신 시작할 때 `--root` 전체를 읽으므로 첫 화면이 늦게 뜹니다. 홈 디렉토리 기준으로 이 기기에서 약 1~3초였고, 메모리는 약 60MB였습니다. `/` 전체는 약 14초에 약 220MB(노드 240만 개)였습니다.
- 현재 폴더가 `--root` 밖이면 `--root`에서 시작합니다.
- `--root`보다 위로 올라가면 그때 부모의 나머지만 읽어 이어 붙입니다. (`p` 키로 미리 넓혀 둘 수도 있습니다.)
- 존재하지 않는 경로이거나 폴더가 아니면 오류 메시지와 종료 코드 2로 끝납니다.

### 읽지 못한 경로 (오류 목록)

스캔 중 권한 등으로 읽지 못한 경로는 조용히 넘어가지 않고 화면에 표시합니다.

- **목록의 각 항목**: 그 항목 안(하위 전체)에서 읽지 못한 경로가 있으면 `⚠ 읽지 못함 N`이 붙습니다. 항목 자체를 읽지 못한 경우에도 목록에서 사라지지 않고 크기 0으로 남습니다.
- **헤더의 합계**: 읽지 못한 경로가 하나라도 있으면 `합계: ≥ 128.1 GB`처럼 "이상"을 뜻하는 `≥`가 붙습니다.
- **`e` 키**: 읽지 못한 경로 전체를 목록 팝업으로 확인합니다.
- **`r` 키**: macOS가 폴더 접근 허용 여부를 묻는 팝업을 띄웠거나 설정에서 권한을 바꿨다면, 허용한 뒤 `r`로 현재 폴더를 다시 스캔해 결과를 갱신합니다.

- 팝업이 열려 있는 동안에는 `j`/`k`(또는 `↑`/`↓`)로 스크롤하고, `e` / `Esc` / `q`로 닫습니다. 팝업이 열려 있을 때 `q`와 `Esc`는 앱을 종료하지 않고 팝업만 닫습니다.
- 각 줄은 `[사유] 경로` 형식입니다. 사유는 `허용 안 됨`(EPERM), `권한 없음`(EACCES), `사라짐`(스캔 중 삭제됨, ENOENT)이며, 그 외는 `오류 <번호>`로 표시됩니다.
- 오류가 매우 많아도 메모리를 아끼기 위해 앞 2000건까지만 목록에 담고, 헤더에는 전체 건수가 표시됩니다.
- **읽지 못한 폴더의 크기는 0으로 집계되므로, 표시되는 합계는 실제보다 작을 수 있습니다.**
- macOS는 사진, 음악, Safari, 휴지통 같은 일부 폴더를 앱이 읽지 못하게 보호합니다. `허용 안 됨`이 많이 보이면 시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한에서 터미널 앱을 허용한 뒤 터미널을 다시 시작하면 줄어들 수 있습니다.

## 용량 계산 방식

- **디스크 사용량 기준**: 파일의 논리 크기가 아니라 실제 할당된 크기를 합산합니다. Finder의 "디스크 사용량"과 비슷한 값입니다.
- **읽기 방식**: macOS의 `getattrlistbulk(2)`로 폴더 안 모든 항목의 이름·종류·할당 크기를 시스템 콜 한 번에 읽습니다. 항목마다 `lstat`을 부르는 방식과 같은 결과를 내면서 호출 수가 훨씬 적습니다.
- **병렬 스캔**: 폴더 순회는 `rayon`으로 병렬 처리합니다. 스레드 수는 `min(CPU 코어 수, 16)`입니다. 16코어 기기에서 측정했을 때 16스레드까지는 스레드가 늘수록 빨라졌지만, 20스레드 이상에서는 5~7초씩 멈추는 현상이 반복되어 상한을 두었습니다. `--threads` 옵션(우선)이나 `RAYON_NUM_THREADS` 환경 변수로 바꿀 수 있으며, 직접 지정한 값은 상한 없이 그대로 사용됩니다.
- **폴더 크기**: 하위 항목을 재귀적으로 합산합니다.
- **스캔 트리(캐시)**: 합산하는 김에 모든 하위 폴더의 항목 목록과 크기를 메모리 트리에 보관합니다. 홈 디렉토리(노드 약 49만 개) 기준으로 앱 메모리는 약 60MB였습니다. `r`로 일부만 다시 스캔하면 그 폴더 아래만 새로 읽어 트리에 끼워 넣고, 상위 폴더들의 크기와 정렬은 자동으로 다시 계산됩니다.
- **심볼릭 링크**: 따라가지 않습니다. 순환 참조를 막기 위해서입니다.
- **권한 없는 경로**: 읽을 수 없는 하위 디렉토리는 0 바이트로 집계하고 오류 목록에 기록합니다. (이동하려는 폴더 자체를 열 수 없을 때는 푸터에 경고가 표시됩니다.)
- **하드 링크**: 링크마다 각각 합산됩니다.

## 프로젝트 구조

```
src/
├── main.rs     # 옵션 처리, 터미널 초기화, 이벤트 루프, 키 입력 처리, 종료 시 터미널 복구
├── cli.rs      # 명령줄 옵션 파싱 (--threads, --help)과 도움말 텍스트
├── scanner.rs  # 스캔 트리(Node) 생성, 부분 갱신 (getattrlistbulk + rayon, UI와 무관한 로직)
├── app.rs      # 앱 상태, 트리 안에서의 폴더 이동, 백그라운드 스캔 스레드와 결과 반영
└── ui.rs       # ratatui 렌더링 (헤더 / 목록 / 푸터)
```

cargo build            # 디버그 빌드

cargo clippy           # 린트 (clippy 컴포넌트 필요: rustup component add clippy)
